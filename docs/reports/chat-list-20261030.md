## 구현과 API 계약

`GET /api/v1/chat-rooms?page=0&size=20`은 기존 본인 참여 전체 목록이다. 선택적 `listingId`를 지정하면 `(sellerId = actor OR inquirerId = actor) AND listingId = requestedListingId`를 DB의 페이지 조회와 count 양쪽에 적용한다. 양수가 아닌 필터는 400, 유효한 양수지만 본인 방이 없는 글은 존재 여부와 무관하게 200·빈 items·총건수 0이다. 기본 크기 20, 최대 100, 최근 메시지 시각 또는 생성 시각 내림차순 후 방 ID 내림차순을 유지한다.

actor는 인증 정보만 사용한다. 제품 ID로 묶거나 현재 소유자에게 과거 대화를 넘기지 않는다. 기존 방의 메시지 조회·전송·읽음 권한과 생성/재사용 정책을 유지한다. 스키마·Migration 변경은 없다.

전체와 상세 목록은 `chat-room-list.js`의 API·텍스트 행 렌더링·더 보기를 공유한다. 사이드바·상단·마이페이지는 전체 목록의 첫 페이지를 연다. 본인 상세와 관리 편집기 바깥에는 실제 상세 응답의 listingId로 해당 글의 목록을 직접 표시한다. 빈 목록·로그인 필요·통신 실패와 재시도를 구분한다.

구매자 문의 버튼은 기존 생성/재사용 API를 호출한다. 반환 roomId와 해당 글의 본인 목록 요약으로 대화를 열어 전체 첫 50개에 의존하지 않는다. 로그인만으로 방이나 메시지를 만들지 않으며 상세 복귀 주소를 보존한다. 공개 상세의 종료글 차단은 유지하고, 종료방의 기존 polling과 메시지 송수신은 유지한다.

화면·방·계정 전환 시 세대 검증과 요청 취소로 이전 응답을 폐기한다. 상세 A와 B, 상세와 전체 목록의 상태를 분리한다. 전송 중 중복 클릭을 막고 초기화 listener와 polling timer를 하나만 유지한다. 목록 미리보기는 읽음 위치를 변경하지 않고 실제 읽음 갱신 성공 후 표시를 반영한다.
