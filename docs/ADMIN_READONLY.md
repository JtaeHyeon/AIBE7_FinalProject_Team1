# 관리자 조회 (ADM-01~04)

## 범위와 접근

관리자는 홈 헤더의 관리자 링크 또는 /admin에서 거래·취소 기록과 업무 변경 기록을 조회한다.
화면과 API는 매 요청마다 users의 현재 ADMIN 역할을 확인한다. 비로그인은 401, 일반 회원은 403이다.
이전 JWT에 ADMIN이 남아 있어도 권한 회수 후에는 접근할 수 없다.
로그인 응답과 /api/auth/me에 추가된 role은 메뉴 표시에 사용하며, 서버 인가를 대신하지 않는다.

계정 생성·관리자 승격 API나 기본 비밀번호는 제공하지 않는다. 관리자 계정 지정은 팀의 계정 운영 절차를 따른다.
화면에서 거래 상태·소유권·이력 원기록을 수정·삭제하거나 강제 취소할 수 없다.

## 화면

- 검색 조건은 PC·태블릿·모바일에서 항상 표시한다.
- 거래 목록: 검색 결과 순번, 제품명·제조사·모델, 판매자/구매자 닉네임·이메일, 거래 상태와 예약 시각.
- 거래 상세: 연결된 판매글, 당사자, 요청/거래 상태, 예약·완료·취소 시각, 취소 사유·수행자.
- 업무 목록: 제품, 행위, 처리 회원 또는 시스템, 결과와 처리 시각. ‘판매글 게시’도 한글 표시·검색을 지원한다.
- 업무 상세: 이력 정정·무효 등 달라진 항목의 전후 값과 사유를 비교한다.
- 기존 DB ID는 상세의 접힌 ‘기록 식별 정보’에서 확인한다. 목록 순번은 DB ID가 아니며 페이지를 넘어 이어진다.
- 네이티브 dialog 상세 패널은 Escape/닫기로 닫고 원래 목록 버튼에 포커스를 돌린다.

제품명·닉네임·이메일은 현재 DB 값이다. 거래 당시 명칭이나 이메일의 사본을 저장하지 않는다.
시스템 처리(actorId=null)와 탈퇴한 회원(actorId가 있으나 회원 조인 결과가 없음)을 구분한다.
화면 시각은 KST, 날짜 검색 조건은 UTC다.

## API

| API (모두 GET) | 응답 |
| --- | --- |
| /api/v1/admin/trades | 구매 요청 기반 거래 목록 |
| /api/v1/admin/trades/{id} | 거래 상세와 취소 메타데이터 |
| /api/v1/admin/audit-logs | 업무 변경 기록 목록 |
| /api/v1/admin/audit-logs/{id} | 허용된 변경 전후 업무 값과 사유 |

공통 목록 파라미터:
- page=0, size=20 (1~100)
- productQuery: 제품명·제조사·모델 부분 검색, 최대 200자
- memberQuery: 닉네임·이메일 부분 검색, 최대 254자
- productId, actorId: 기존 식별자 검색
- from, to: UTC 날짜, 종료일 포함. 거래는 예약일, 업무 기록은 처리일 기준

거래의 status는 PENDING/REJECTED/RESERVED/COMPLETED/CANCELLED다.
거래의 회원 검색은 판매자·구매자·취소 수행자, 업무 기록은 처리 주체를 대상으로 한다.
업무 기록은 action으로 필터링한다. 영문 대소문자를 구분하지 않는 부분 검색이며 SQL 와일드카드도 문자로 취급한다.
거래는 요청 ID 내림차순, 업무 기록은 처리 시각·ID 내림차순이다.

## 구조와 연동 조건

SecurityConfig → AdminAccessService → AdminAccessRepository가 현재 관리자 여부를 확인한다.
AdminController → AdminReadService → AdminReadRepository가 조회한다.
서비스는 읽기 전용 트랜잭션이며 목록 건수와 항목을 같은 스냅샷에서 읽는다.
제품·회원 정보를 SQL 조인으로 투영하므로 항목별 추가 조회를 하지 않는다.

거래 조회는 기존 app.features.trade-purchase-requests.enabled=true와 해당 P2/P3 스키마가 적용된 환경에서 이용한다.
기능이 꺼진 환경은 503/ADMIN_001로 안내한다. 이 변경에는 새 마이그레이션이나 기존 마이그레이션 수정이 없다.

예약·완료 시각은 해당 제품·구매 요청에 연결된 PURCHASE_REQUEST_ACCEPTED/TRADE_COMPLETED 성공 감사 기록의 시각을 사용한다.
예전 데이터에 기록이 없으면 null/‘—’로 표시하며 추정하지 않는다.
예약 전 취소된 요청에는 예약 시각이 없을 수 있다. 취소 메타데이터는 구매 요청에 저장된 값을 읽는다.

## 데이터 보호

- 관리자 DTO에 필요한 업무·회원 요약만 반환한다. 회원 엔티티, 비밀번호 해시, 제품 시리얼은 포함하지 않는다.
- 비공개 증빙 사본·경로와 채팅 본문은 조회하지 않는다.
- AdminAuditFacts는 알려진 이력·사양·거래 필드만 선별한다. 임의 JSON이나 해석하지 못한 예전 원문을 그대로 반환하지 않는다.
- 이력 정정·무효의 내용·업체·비용·사양과 사유는 ADM-03 업무 정보다. 자유 입력 자체의 개인정보 자동 마스킹 기능을 의미하지 않는다.
- 응답은 no-store이며 브라우저 저장소에 기록을 보관하지 않는다.
- 탭 숨김·화면 이탈 때 데이터를 지우고 복귀 시 다시 인가·조회한다. 취소와 요청 세대 검사로 늦은 응답을 버린다.
- 사용자 입력은 textContent로 표시한다. 검색어는 SQL 매개변수로 바인딩한다.

## 검증

AdminHttpTest는 실제 JWT 필터·HTTP·DB로 관리자 접근, 권한 회수, 조회/필터/페이지 구분, 취소 메타데이터,
회원·제품 요약, 비공개 필드 제외와 읽기 전용 동작을 검증한다.
기본 H2 실행은 조회용 P2 fixture를 사용한다.
SALE_DRAFT_TEST_DB_URL에 전용 sale_ai_test PostgreSQL DB를 지정하면
독립 스키마에 정식 일반/P2/P3 Flyway를 적용해 같은 시험을 실행하고 그 스키마만 정리한다.
CI의 PostgreSQL 작업에도 이 테스트를 포함한다.

AdminAuditFactsTest는 허용 필드·사양 투영과 지원하지 않는 원문 차단을 검사한다.
src/test/js/admin.test.mjs는 실제 화면 JS를 DOM 대역으로 실행해 비동기 응답, 권한 상실, 안전한 표시와 dialog 복귀를 검사한다.
이 시험은 실제 브라우저의 레이아웃 검증을 대신하지 않는다.

  검색/초기화, 페이지 간 연속 순번, 변경 비교와 Escape/포커스 복귀 확인
