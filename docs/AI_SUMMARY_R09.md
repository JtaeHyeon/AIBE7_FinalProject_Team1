# 현재 화면과 요약 길이

사용자의 카드 중심 요구에 맞춰 현재 구현은 1~2문장·90자 이내 요약을 회원용 마켓 카드에 표시한다.
아래 내용은 R09 최초 구현 기록이며, 현재 표시 위치·형식과 기존 데이터 전환은 [카드 요약 변경](AI_LISTING_CARD_SUMMARY.md)을 따른다.

# R09 판매글 상세 AI 제품 상태 요약

[WBS](https://app.notion.com/p/3f23550b7b55802ca75ceaff66e09a52)의 R09-1~3, 요구사항 AI-03·AI-08과 ERD listings 요약 컬럼을 구현한다.
R08의 작성자용 제목·본문 제안과 달리, 게시된 ACTIVE/RESERVED 판매글의 회원용 상세에 3~5문장 상태 요약을 제공한다.
실제 이력 원천의 운영 어댑터는 여전히 필요하며 샘플·테스트 대역을 운영 연동 완료로 간주하지 않는다.

## API와 화면

| Method | 경로 | 역할 |
|---|---|---|
| GET | `/api/v1/listings/{listingId}/summary` | 로그인 회원이 공개 가능한 요약 상태·내용 조회. 모델 호출·생성 접수 없음 |
| POST | `/api/v1/listings/{listingId}/summary` | 게시자이자 현재 소유자만 최초 생성·실패 재시도 접수, 202 반환 |
| GET | `/api/v1/listings/{listingId}` | 기존 상세 응답에 같은 `summary` DTO 포함 |

응답은 `status`, `text`, 안전한 `errorCode`, `updatedAt`, `canRequest`, `retryAfterSeconds`다.
상태는 NOT_REQUESTED·QUEUED·PROCESSING·READY·FAILED다. R09에서는 text를 검증된 READY에서만 제공했으며, [R10](AI_SUMMARY_REFRESH_R10.md)은 갱신 중 이전 문장을 `outdated=true`로 구분해 제공한다.
생성 시도 UUID·입력 JSON·공급자 응답·키는 공개하지 않는다. JSON은 no-store이며 기존 쿠키 CSRF 검사를 유지한다.
요약 생성 자체의 실패와 원천 이력 장애는 구분한다. 기존 상세의 소유권·공개 상태·이력 준비 검사에서 거부되는 경우에는 기존 404/503 계약을 완화하지 않는다.

- 상세·미리보기 공통 렌더러에서 실제 게시글에만 AI 요약 영역을 추가한다. 작성 중 미리보기에서는 생성하지 않는다.
- 대기·처리 중에는 2초 간격으로 최대 30회 상태를 조회하고 이후 수동 새로고침을 제공한다. 완료 상태에서는 상세가 활성 상태인 동안 15초 간격으로 종료 여부를 확인한다.
- 실패해도 기존 사양·설명·사진·이력은 유지하며 판매자에게만 재시도를 제공한다.
- 실패 후 기본 60초 재접수 제한을 표시한다. 비회원·다른 회원은 생성 비용을 유발하는 접수를 할 수 없다.
- 판매 종료·권한 상실을 404/401로 확인하면 요약뿐 아니라 이전 상세 표시도 비운다. 화면 이탈·제품 변경 시 요청과 타이머를 취소하며 늦은 응답을 버린다.
- 탭 재활성화와 bfcache 복귀 시 상태·권한을 재확인한다. 모든 AI 결과는 textContent로 표시한다.
- 게시 확인 창에 공개 제품 정보·이력을 요약 생성에 사용하는 사실을 안내한다.

## 비동기 처리

1. 최초 게시 트랜잭션에서 `ListingPublished` 이벤트를 발행한다. 게시 재시도는 같은 판매글을 반환하고 이벤트를 다시 발행하지 않는다.
2. AFTER_COMMIT 수신자가 REQUIRES_NEW 트랜잭션으로 QUEUED를 저장한다. 접수 오류는 이미 성공한 게시를 오류로 바꾸지 않으며 판매자가 명시적으로 다시 요청할 수 있다.
3. 기본 1초 주기의 디스패처가 DB의 QUEUED 작업을 읽는다. 작업자 2개·실행 대기 10개로 제한하고 포화 상태에서는 DB 대기열을 유지한다.
4. 제품 → 판매글 순서로 잠근 뒤 QUEUED→PROCESSING 조건부 전이와 시도 번호로 중복 실행을 막고 공개 허용 입력을 구성한다.
5. 트랜잭션·DB 잠금을 해제하고 기존 Redis 요청 제한을 획득한 뒤 Gemini를 호출한다.
6. 3~5개의 고유한 한 문장·문장당 최대 650자·전체 최대 2,000자를 검사한다. 작성 지침이 섞였거나 확인 가능한 제품 사실이 빠진 결과를 거부하고 R08의 민감정보·금지 표현·미등록 수치 보조 검사도 수행한다.
7. 새로운 짧은 트랜잭션에서 현재 판매 상태·소유권·제품 버전·판매글 버전·시도 ID·전체 공개 자료 지문을 확인한 뒤 READY를 저장한다.
8. 실패는 입력·공급자 원문 없이 안전한 AI 오류 코드만 FAILED에 저장한다. 종료·소유권 변경 후 도착한 결과나 이전 시도는 저장·공개하지 않는다.

접수·상태 조회는 모델 응답을 기다리지 않는다. 기본 기한은 R08과 같은 20초이며, Redis의 회원별 동시 1개·분당 3회·전체 분당 30회를 작성 제안과 공유한다.
모델 처리 중 잠금은 유지하지 않으므로 정상적인 판매 중지·소유권 변경을 막지 않는다.

DB 대기열을 사용하므로 재시작 후 QUEUED 작업을 다시 읽는다. PROCESSING은 모델 기한+60초, QUEUED는 5분을 넘으면 실패로 복구한다.
FAILED를 자동 반복 생성하지 않아 장애 중 비용을 무제한 사용하지 않는다. 같은 버전의 QUEUED/PROCESSING과 품질 검사에서 재사용 가능한 READY 재접수는 같은 시도를 유지한다.

## 데이터 범위와 정확성

- R08 공개 허용 제품 정보와 **전체** 누적 핵심 이력 원천을 재사용한다. 이전 소유자·정정·무효 표시를 포함한다.
- 무효·미검토 이력의 자유 입력은 보내지 않고 기록의 존재·날짜·상태를 남긴다. 무효는 실제 수리·교체 사실·횟수로 단정하지 않도록 지시한다.
- 이력이 없으면 등록된 기록으로 확인할 수 없다고 안내하고 수리·고장 없음을 단정하지 않는다. 구매일 경과를 실제 사용 기간으로 바꾸지 않는다.
- 구조화된 판매자 선택 등급은 판매자의 주장으로 구분한다. AI가 품질·안전·정품·가격·구매 적합성을 판정하지 않는다.
- 판매자의 자유 입력 제목·설명·가격은 모델 입력에 포함하지 않는다. 시리얼·계정·비용·사진·문서·채팅도 보내지 않는다. 판매 조건 변경은 content_version으로 감지한다.
- 전체 입력은 UTF-8 48KB 한도를 유지하며 초과 시 일부 이력을 조용히 생략하지 않고 실패한다.
- 생성 전후의 자료 지문 검사 외에 조회 시 products.facts_version과 content_version도 검사해 오래된 READY 내용을 내보내지 않는다. 원천의 사실·공개 범위 변경은 facts_version을 증가시켜야 한다.
- 정규식과 문장 수 검사는 모든 개인정보·의미상 오류를 증명하지 않는다. 원천의 개인정보 검토와 결과의 의미 검증이 계속 필요하다.

## DB·설정

`V2026102601__add_listing_ai_summary.sql`이 기존 listings에 ERD의 7개 컬럼을 추가한다.

- summary_text
- summary_source_product_version
- summary_source_listing_version
- summary_status
- summary_attempt_id
- summary_error_code
- summary_updated_at

기존 행은 모두 NULL인 미요청 상태로 보존한다. DB CHECK가 불완전한 상태 조합과 음수 버전을 막고 상태·시각 인덱스로 대기 작업을 읽는다.
JPA 판매글 엔티티와 요약의 JDBC 변경 열을 분리해 판매 조건 수정이 요약 상태를 덮어쓰지 않는다.
스키마 변경은 기존 마이그레이션 수정 없이 새 Flyway 파일로만 적용한다. 새 의존성은 없다.

```dotenv
GEMINI_API_KEY=로컬에서_실제키_설정
AI_MODEL=gemini-3.5-flash-lite
AI_SUMMARY_ENABLED=true
```

R08의 Gemini 전송·구조화 출력·전체 응답 기한·수신 크기·키 숨김 처리를 `GeminiJsonClient`로 공유한다.
기준은 공식 [모델](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)과 [구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) 문서다.
test 프로필에서는 자동 처리를 기본 비활성화해 개발자의 실제 API 키로 비용이 발생하지 않게 한다. R09 테스트만 명시적으로 활성화하고 AI 대역을 주입한다.

## 2026-10-27 로컬 게시 오류 수정

- 기존 파일 H2 DB를 R09로 업데이트한 뒤 게시 시 HTTP 500이 발생했다. `CHECK(status IN (...))` 평가가 이미 닫힌 DDL 연결을 참조하는 H2 2.4.240 오류를 별도 DB 복사본에서 재현했다.
- H2를 2.5.250으로 지정했다. 공식 [수정 PR](https://github.com/h2database/h2database/pull/4311)과 [릴리스](https://github.com/h2database/h2database/releases/tag/version-2.5.250)에 해당 수정이 포함된다. PostgreSQL 의존성과 운영 마이그레이션은 변경하지 않는다.
- 시연 DB에는 가상 판매자 1·2도 누락되어 있었다. 새 **시연 전용** `V2026102700__restore_missing_demo_sellers.sql`이 없는 계정만 복구하며 기존 계정·초안·사진을 수정하지 않는다. 일반 Flyway 실행에는 시연 디렉터리가 포함되지 않는다.
- `ListingDemoUpgradeTest` 2건으로 파일 DB 재개방→별도 연결의 마이그레이션→게시·요약 상태 저장, 초안·사진 보존과 기존 계정 보존을 검증했다. 기존 마이그레이션은 수정하지 않았다.
- 수정 후 `spotlessCheck test build` 성공. 전체 469건 중 448건 성공, 환경 조건으로 기존 거래 20건·Redis 1건 제외, 실패·오류 0건.
- 기존 18081 작성본을 실제 브라우저에서 게시해 판매글 33번 생성과 `listingId=33` 상세 이동을 확인했다. 실제 Gemini 호출 1회에서 READY 결과가 저장됐다. 원천 이력은 시연용 샘플이며, 생성 문장이 처리 규칙 안내에 치우쳐 있어 사용자에게 유용한 문장 품질은 별도로 개선·검토해야 한다.

## 2026-10-27 요약 문장 품질 보완

### 변경한 동작

- Gemini에 제품명·주요 사양·누적 이력을 구매자가 읽을 수 있는 문장으로 요청한다. 정정·무효·미검토 이력과 빈 이력을 보여주는 입출력 예시를 추가했다. 원문이 완결된 문장일 때 이를 그대로 붙여 한 항목에 두 문장이 생기는 경우도 예시로 보완했다.
- 이력 유형의 한국어 표현을 명시했다. 예를 들어 TRANSFER는 제품 양도 이력이다. 예시의 사양·날짜를 실제 제품에 복사하지 않도록 구분한다.
- `ListingSummaryTextPolicy`가 내부 필드명·상태 코드·작성 지침을 반복하는 결과를 거부한다. 실제 발생했던 규칙 안내 문장은 회귀 테스트로 남겼다.
- 모델명·CPU·메모리 등 확인 가능한 제품 사실이 입력에 있으면 결과에도 적어도 하나가 포함되어야 한다. 띄어쓰기·대소문자를 정규화해 비교한다. 등급·일반 안내만 있는 결과는 거부하며, 자료가 부족한 제품에 없는 사양을 요구하지 않는다.
- 새 결과가 검증에 실패하면 `FAILED / AI_003`으로 처리하고 결과 문장은 저장·공개하지 않는다. 기본 판매글 상세 조회는 계속 가능하다.
- 이미 저장된 READY 문장도 알려진 작성 지침 반복 패턴이면 GET 응답에서 내용을 숨기고 `FAILED / AI_003`으로 제공한다. 이 조회는 DB를 수정하거나 Gemini를 호출하지 않는다. 판매자가 명시적으로 POST하면 같은 제품 버전에서도 새 시도로 생성할 수 있다.
- API·스키마·의존성을 추가하지 않았으며 R08의 공통 전송·요청 제한·개인정보 검사를 유지한다.

프롬프트 예시 구성은 공식 [프롬프트 전략](https://ai.google.dev/gemini-api/docs/prompting-strategies)을 참고했다. 기존 [구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) 스키마와 별도로 애플리케이션의 결과 검증을 적용한다.

### 검증과 한계

- 실제로 노출되었던 규칙 안내와 제품 사실 없는 문장이 기존 검사를 통과하는 문제를 먼저 재현한 뒤 수정했다. 자연스러운 정정·무효 설명과 자료가 부족한 제품 설명은 허용하는지도 검사한다.
- HTTP 테스트로 검증 실패 시 원문 미저장·미공개, 기존 잘못된 READY 내용 숨김, GET의 모델 미호출, 판매자만 명시적으로 새 생성 가능 여부를 확인했다.
- 초기 문장 품질 보완 후 `spotlessCheck test build` 성공. 전체 493건 중 470건 성공, 환경 조건에 따른 기존 테스트 23건 제외, 실패·오류 0건이다. 로컬 Docker가 꺼져 있어 프로세스 환경 변수로 H2 PostgreSQL 호환 모드와 Flyway를 사용했다. 실제 `.env`와 사용자 DB는 수정하지 않았으며, 제외된 PostgreSQL·Redis 테스트를 실행 완료로 간주하지 않는다.
- 공개 가상 제품 자료로 실제 `gemini-3.5-flash-lite` 전송·문장 검증을 확인했다. 초기 프롬프트를 조정하며 4차례에 걸쳐 총 12회 호출했으며 자동 재시도는 사용하지 않았다. 마지막 세 사례는 모두 검증을 통과했다. 실제 공급자 확인과 AI 대역을 사용하는 HTTP·DB 검증은 별개다. 화면·저장 흐름 확인은 아래 날짜 표기 수정 후 추가로 진행했다.

| 실제 공급자 최종 표본 | 확인한 내용 |
|---|---|
| 사양과 이력이 있는 MacBook Pro 14 | 메모리 18GB·SSD 512GB, 구매·양도·정정된 점검 내용과 무효 수리 기록을 구분 |
| 이력이 비어 있는 ThinkPad X1 Carbon Gen 12 | 등록 사양과 빈 이력을 설명하며 수리·고장이 없다고 단정하지 않음 |
| 미검토·무효 이력이 있는 Galaxy Book | 세부 내용이 검토 중인 수리 기록과 무효 처리된 수리 기록을 구분 |

- 제품 사실 포함 여부와 알려진 규칙 표현 검사는 보조 장치다. 모든 문장의 사실 관계를 증명하거나 모든 부자연스러운 문장을 탐지하지는 않는다. 유한한 실제 호출 표본만으로 향후 결과 품질을 보장하지 않는다.
- 운영 이력 어댑터 연결과 R10의 변경 이벤트 기반 자동 최신화는 후속 작업으로 남아 있다.

### 같은 날짜의 표기 차이로 발생한 검증 실패 수정

- 33번 판매글의 공개 자료를 사용한 실제 Gemini 응답에서 `2024-02-12`가 `2024년 2월 12일`로 출력되는 실패를 재현했다. 공통 숫자 검사가 `02`와 `2`를 다른 값으로 판단해 정상 날짜도 `AI_003`으로 거부했다.
- R09 검증에서 제품 구매일·보증 만료일·이력 발생일에 등록된 날짜만 수집한다. 결과의 연월일을 실제 달력 날짜로 파싱하고, 등록된 날짜와 일치할 때만 ISO 표기로 맞춘 뒤 기존 문장·민감정보·숫자 검사를 수행한다. R08의 공통 숫자 검사를 완화하지 않는다.
- 등록되지 않은 날짜 조합·존재하지 않는 날짜, 날짜 밖의 새 사양 숫자, 표기를 맞춘 뒤 중복되는 문장은 거부한다. 한글 날짜 표기·월일 앞의 0 생략·보증 만료일의 저장과 HTTP 반환도 회귀 테스트에 포함했다.
- 실패를 재현한 공급자 응답을 그대로 재검증해 외부 재호출 없이 통과하는 것을 확인했다.
- 수정 후 `spotlessCheck test build` 성공. 전체 504건 중 481건 성공, 환경 조건으로 23건 제외, 실패·오류 0건이다. 시연 서버에도 수정된 빌드를 반영했다.
- 사용자가 33번 판매글에서 실제 Gemini 요약을 다시 생성해 화면의 5문장 설명을 확인했다. 이후 별도 요약 GET에서 `READY`와 오류 코드 없음, 판매글 상세의 요약과 같은 내용이 재조회되는 것을 확인했다. 이 확인의 이력 원천은 로컬 샘플이며 운영 이력 연동 완료를 뜻하지 않는다.
- 생성 지침·날짜 표기 보정·결과 검증·이전 요약 재생성 조건에 필요한 설명 주석을 추가했다. 주석 외 코드가 바뀌지 않았음을 비교하고 `spotlessCheck`도 다시 통과했다.
