# 소유권 이전 후 판매 초안 정리

요구사항 OWN-06에 따라 이전 소유자의 비공개 판매 초안은 이전 완료와 함께 삭제한다. 초안이 남으면 제품당 한 개 제약 때문에 새 소유자의 새 초안 작성도 막히므로, 접근 차단만으로 처리를 끝내지 않는다.

## 동작

1. 기존 `OwnershipTransferService.acceptTransfer`가 제품 → 이전 요청 순서로 잠그고 수신자·만료·현재 소유자를 검사한다.
2. 소유자와 이전 상태를 바꾼 뒤 `OwnershipTransferred(productId, previousOwnerId, newOwnerId)`를 같은 트랜잭션에서 발행한다.
3. `ListingDraftService.ownershipTransferred`가 새 소유권을 다시 확인하고 해당 제품의 이전 작성자 초안을 JPA로 삭제·flush한다. 초안의 `draft_images` 선택 관계만 함께 삭제하며 제품·제품 사진·다른 제품의 초안은 유지한다.
4. 감사 기록까지 성공해야 함께 커밋한다. 초안 삭제나 이후 감사 저장이 실패하면 소유자·이전 상태·초안·사진 선택도 모두 되돌린다.

동기 `@EventListener`와 `Propagation.MANDATORY`를 사용한다. 커밋 뒤 비동기로 삭제하면 새 소유자의 작성과 경합하므로 커밋 후 이벤트로 바꾸지 않는다. 기존 초안 저장도 같은 제품 행 잠금을 사용한다. 이전 소유자의 늦은 저장은 이전 완료 후 권한 검사에서 거부된다.

중복 알림으로 새 소유자의 초안을 지우지 않도록 작성자가 현재 새 소유자인 초안은 보존한다. 잘못된 새 소유자나 트랜잭션 없는 이벤트는 삭제 전에 거부한다. 새 소유자는 이전 글 내용을 승계하지 않고 새 ID로 작성하며, 과거 ID·버전으로 새 초안을 수정·삭제할 수 없다. 커밋 전에는 새 소유권이 다른 요청에 보이지 않으므로, 그때의 새 소유자 요청은 404일 수 있으며 완료 후 다시 요청한다.

## 연결 범위

- 현재 운영 코드에 있는 토큰 기반 이전 수락 경로에 연결했다. 새 HTTP API·화면·마이그레이션·외부 의존성은 추가하지 않는다.
- 거래 P4의 `InternalTradeCompletionPort`는 아직 정식 운영 구현이 없다. 향후 구현에서도 소유자 변경 후 제품 잠금을 유지한 같은 트랜잭션에서 이 이벤트를 발행해야 한다. 이번 변경만으로 내부 거래 완료 전체가 연결된 것은 아니다.
- 과거에 이미 완료된 이전의 고아 초안에 대한 일괄 삭제는 실행하지 않는다. 기존 개발 DB와 시연 데이터도 이 작업을 위해 수정하지 않는다.

## 검증

`ListingDraftOwnershipHttpTest`는 실제 Spring HTTP·JWT·CSRF·정식 Flyway·JPA·JDBC를 사용한다. Redis의 반복 요청 제한만 시험 대역이며, 삭제 실패는 시험 전용 FK로, 삭제 후 실패는 실제 감사 INSERT 뒤 예외로 주입한다. 경합 시험은 이전이 제품 잠금을 유지한 상태에서 상대 요청의 잠금 진입을 확인한다.

- 정상 수락, 초안 없음, 다른 제품 초안·제품 사진 보존, 새 소유자의 새 작성
- 이전 소유자의 오래된 조회·저장·삭제·미리보기 차단과 새 소유자의 과거 ID·버전 거부
- 요청 생성·취소·만료·수신자 오류·본인 수락에서 초안 보존
- 초안 삭제 실패와 이후 감사 실패의 전체 롤백 및 재시도
- 이전 소유자의 동시 저장, 커밋 전 새 소유자의 요청과 완료 후 작성, 중복 알림의 새 초안 보존
- 트랜잭션·현재 소유권 검사와 쿠키 인증 CSRF 차단

- `spotlessCheck test build` 성공: 전체 885개 중 802개 성공, 환경 조건으로 83개 제외, 실패·오류 0개. 실행 중인 이전 빌드 파일을 보존하기 위해 로컬 init script로 bootJar 파일 이름만 변경했다.
- 새 HTTP 통합 14개와 기존 이전 서비스 단위 14개 통과. 새 HTTP 14개는 별도 PostgreSQL DB에서도 모두 통과했다.
- 기존 게시 제약 HTTP 시험 12개도 별도 PostgreSQL DB에서 통과했다. 이전 후 초안이 남는다는 과거 기대값을 삭제 정책으로 바꾸고, 실제 게시 차단과 선택 관계 삭제를 검사한다. Redis 요청 제한은 업무 검증과 분리했다.
- 전용 PostgreSQL 시험 스키마·DB는 검증 뒤 제거했다. 18082 복제 DB 서버는 새 빌드로 재시작했으며 기존 Q&A도 포함한다.
