# 실제 제품 이력 조회 연결

## 구현 범위

`JdbcListingHistoryReader`가 제품 이력과 정정·무효 기록을 `ListingHistoryReader`에 연결한다. 기존 `ListingPublicationService`가 이 결과를 정렬·권한 검사·페이지 처리하여 작성 화면의 공개 예정 정보, 미리보기, 회원용 상세와 AI 입력에 제공한다. 이력 모듈에 새 HTTP API를 요구하거나 기존 이력 응답 형식을 바꾸지 않는다.

- 제품 ID 기준 전체 누적 이력을 조회한다. 이전 소유자 기록·무효 기록·시스템 소유권 이전 기록을 유지한다.
- 정정·무효 감사 기록은 마지막 한 건으로 줄이지 않고 실제 ID·시각을 제공한다. 다른 업무 감사 기록과 다른 제품의 기록은 제외한다.
- 현재 원천에는 공개용 본문·사유의 검토 완료 근거가 없다. 제목·본문·업체·부품·정정 사유·비용·문서·감사 전후 원문을 SQL에서 읽지 않으며, 공개용 텍스트는 `reviewed=false`로 둔다.
- 화면은 이력 유형·날짜·정정·무효 표시를 제공하고 자유 입력은 검토 중으로 표시한다. AI도 등록 사양과 이력 메타데이터를 사용하며 미검토 본문을 받지 않는다. 본문까지 공개하는 검토 정책은 후속 범위다.
- 한 번에 이력 최대 10,000건, 정정·무효 기록 합계 최대 10,000건 및 이력 한 건당 최대 100건을 제공한다. 초과하면 일부를 생략하지 않고 이력 연동 오류로 거부한다. 조회는 이벤트 목록과 변경 목록을 묶어서 처리하며 이력별 추가 쿼리를 실행하지 않는다.

## 활성화와 스키마 준비

`LISTING_HISTORY_ENABLED=true` 또는 `app.features.listing-history.enabled=true`로 실제 조회를 활성화한다. 기본값은 false이며, test 프로필에서도 기본 비활성화한다. `sale-draft-demo` 프로필에서는 실제 조회 Bean을 등록하지 않아 기존 샘플 공급자와 겹치지 않는다.

호출자는 기존 판매 서비스에서 현재 소유권을 확인하고 제품 행을 잠근 트랜잭션에 참여해야 한다. 조회 메서드는 `MANDATORY` 전파를 사용하며 외부 API로 노출하지 않는다.

활성화 후 필요한 `product_events`·`audit_logs` 컬럼이 없으면 JDBC 메타데이터로 확인해 `UNAVAILABLE`을 반환한다. 스키마 부재를 실제 이력 없음(`READY`와 빈 목록)으로 처리하지 않는다. 존재하지 않는 테이블에 먼저 SQL을 실행해 PostgreSQL의 호출 트랜잭션을 깨뜨리지 않는다. 원천이 준비된 뒤에는 재시작 없이 다음 조회에서 사용할 수 있다.

원본 main의 PR #50에서 제품 이력 마이그레이션이 `V2026102801__create_product_history.sql`로 변경됐다. 이미 적용된 판매 초안 이미지의 `V2026102002`는 유지한다. 이력 테이블 배포 후 실제 조회를 활성화하며, 이 변경은 기존 DB에 대한 마이그레이션 실행이나 기능 활성화를 대신하지 않는다.

`HistoryService`의 사용자 이력 추가·정정·무효 처리는 제품 버전 증가와 `ProductFactsChanged` 발행까지 연결했다. [이력 변경 후 AI 갱신](AI_HISTORY_REFRESH_INTEGRATION.md)을 참고한다. 이력 공개·비공개 전환, 거래/이전 검사·취소와 향후 문서·소유권 이전 저장 측 연결은 별도 범위다. 실제 조회를 켜는 것만으로 게시·판매 중지의 모든 외부 연결이 완료되지는 않는다.

## 테스트 원천

최신 main의 정식 이력 마이그레이션을 테스트 DB에 Flyway로 적용한다. 이력 DDL의 테스트 복사본은 두지 않는다. HTTP 테스트는 실제 이력 API로 등록·정정·무효 처리한 기록이 판매글 공개 예정 정보에 반영되는지 확인한다. JDBC 단위 테스트는 비공개 본문 컬럼조차 없는 최소 스키마로 조회의 허용 필드만 검증한다.

검증 대상은 실제 SQL 변환, 이전 소유자·무효·전체 정정 정보, 권한과 종료 상태, 공개 응답·AI 입력의 비공개 정보 제외, 스키마 미배포와 실제 빈 이력의 구분 및 조회 한도다. HTTP 검증은 실제 조회 어댑터와 인증을 사용하고 외부 AI는 호출하지 않는다.

## 검증 결과

- 최신 main 통합 후 `clean spotlessCheck test build`: 전체 641개 중 605개 성공, 환경 조건으로 36개 제외, 실패·오류 없음.
- 조회·HTTP 테스트 18개가 H2와 별도 PostgreSQL 테스트 DB에서 각각 통과했다. PostgreSQL에서는 카드 요약·목록·데이터 전환까지 함께 69개를 검증한 뒤 테스트 DB를 정리했다.
- 회원용 상세·소유자 공개 예정 정보와 전체 AI 입력의 연결을 확인했다. 실제 AI 공급자는 호출하지 않았다.
- 팀의 정식 이력 `V2026102801`은 수정하지 않았고, 현재 개발·시연 DB에도 마이그레이션을 실행하지 않았다. 운영 활성화와 공개용 본문 검토 기준 확정은 후속 작업이다.
